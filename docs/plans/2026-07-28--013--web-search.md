## Cel

Agent nie miał żadnego dostępu do internetu — cała wiedza pochodziła z tego, co użytkownik ręcznie wkleił. Ten plan dodaje:

1. `web_search` — agentic wyszukiwanie, 0..N razy na turę, model sam układa zapytania.
2. `web_fetch` — pobranie pełnej treści strony (etap „open"; bez niego zostają same snippety).
3. Blok `sources` — realizacja obiecanych w dec. #14 „odnośników do źródeł", których katalog bloków nie miał.
4. Zero konfiguracji na start (istniejący `OPENROUTER_API_KEY`), z drogą wyjścia do własnego providera.
5. Domknięcie łańcucha `web_search → web_fetch → wiki_ingest` (`wiki_ingest` przyjmował `source_url`, ale nikt tego URL-a nie pobierał).

### Bezpieczeństwo `web_fetch`

`assert_url_allowed()` jest wywoływany **zawsze** — również zanim URL poleci do Tavily, żeby wewnętrzny hostname nie wyciekł do zewnętrznego dostawcy:

- schemat wyłącznie `http`/`https`;
- odrzucenie `localhost`, `metadata.google.internal`, sufiksów `.local` / `.internal` / `.localdomain` / `.home.arpa` oraz hostów z `AI_WEB_FETCH_BLOCKED_HOSTS`;
- **rozwiązanie DNS i sprawdzenie każdego zwróconego adresu** (`is_private | is_loopback | is_link_local | is_reserved | is_multicast | is_unspecified`) — łapie `169.254.169.254` i DNS rebinding, także gdy tylko jeden z kilku rekordów A jest prywatny;
- redirecty ręcznie (`follow_redirects=False`), max 3 skoki, **walidacja na każdym skoku**;
- limit `AI_WEB_FETCH_MAX_BYTES` strumieniowo + allow-lista content-type; HTML bez providera → miękki komunikat „użyj web_search".

### Blok `sources`

`_sources_blocks()` zbiera `outputData["sources"]` z kroków bez `error`, normalizuje URL (obcięcie `utm_*`/`fbclid`/`gclid`, końcowego `/`, lowercase hosta), deduplikuje zachowując kolejność pierwszego wystąpienia, przenumerowuje 1..n i zwraca **jeden** blok. Malformed payload → `logger.warning` i pominięcie.

## Poza zakresem (v2+)

- `RagSourceType.WEB` + `RagService.ingest_from_web()` — bezpośredni `web_fetch(ingest=true)` z pominięciem wiki.
- **URL w wynikach RAG:** `RetrievalHit` / `RagSearchHit` nie niosą `source_ref`, więc materiał znaleziony później przez `rag_search` nie ma klikalnego źródła. Wymaga dołożenia `d.source_ref` do **obu** gałęzi SQL w `rag/repositories.py`.
- Twardy limit wydatków per tenant (`modules/feature_limits/` istnieje, niepodpięty do narzędzi).
- Własna ekstrakcja HTML→markdown niezależna od providera (nowa zależność).
- PDF z sieci, wyszukiwanie obrazów, `find_in_page`, tryb Deep Research.
- Domain allow/deny-lista per agent (kolumna `guardrails` istnieje, nieużywana).

## Ryzyka

| Ryzyko | Mitygacja |
|--------|-----------|
| **Server tools mogą nie zwracać `annotations`** — kształt odpowiedzi nieprzweryfikowany (403 na docs, brak klucza) | `ws-probe`. Harvest jest defensywny (brak pola → pusty wynik). Fallback: plugin `web` (`plugins: [{"id": "web"}]`), który na pewno zwraca `url_citation`, kosztem tego, że nie jest agentic |
| **Płatna zdolność domyślnie włączona** (~$4/1000 wyników; przy `max_results=5` do ~$0.02 na wyszukanie) | `web_search_max_results=5`, cache 15 min, kaskada pozwala wyłączyć na każdym poziomie, koszt opisany w `.env.example`. Twardy cap → v2 |
| Prompt injection z pobranej strony | `<web_page untrusted="true">` + zdanie w obu promptach; `AgentMarkdown` ma już `html: false` + `secureMarkdownHtml()` |
| SSRF / metadata endpoint | `assert_url_allowed` z walidacją po DNS na każdym skoku; 22 testy |
| `AGENT_MAX_STEPS=10` przy fan-oucie | prompt sugeruje kilka wąskich zapytań; do obserwacji, ewentualne podniesienie limitu |
| Provider pada / timeout | kontrakt „degraduj, nie wywalaj" — miękki `message` |
| W trybie `server` brak kroków na żywo w SSE | świadomy koszt zero-configu; syntetyczny krok po turze trzyma audyt i blok źródeł; `local` daje pełen trace |
